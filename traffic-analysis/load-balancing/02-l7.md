# 02 — L7 load balancing (NGINX Ingress in this project)

## What L7 adds

NGINX is not a router. It is an application server that *happens* to be a load balancer. It sees:

- HTTP method, path, host, headers, body.
- TLS (if terminated here).
- The full request/response, including upstream time.

What that lets it do that L4 cannot:

- **Path routing**: `/api/products` → app A, `/api/orders` → app B.
- **Header routing**: `X-Region: eu` → EU backend.
- **TLS termination**: the client sees one cert; the backend can be plain HTTP.
- **Request-size limits**: `client_max_body_size`.
- **Rate limiting**: `limit_req` per IP / per endpoint.
- **CSV access log + request-duration histogram** — the two things that make the L7-vs-L4 latency comparison lab possible.

## The metric you will read most

```
nginx_ingress_controller_request_duration_seconds_bucket
```

One histogram, with labels `{ingress, service, target}` (ingress = the ingress name, service = the k8s service, target = the backend target). This is the *L7 view* of latency — it includes TLS + proxy + upstream + log write.

Compare to the app's `http_request_duration_seconds` — the *intra-app view*. The delta is NGINX's own latency.

## L7 health checks

The `ingress-nginx` controller runs an *HTTP* health check on each backend endpoint: `GET /healthz` (or the configured path), expecting a 200. If it fails, the endpoint is removed from the L7 round-robin.

The L4 layer does not know. The L4 layer is still sending to the pod IP:port. The pod is up (TCP handshake works). The L7 layer is the one that noticed the app is returning 500s.

This is the layering problem: L4 and L7 health checks are *different signals*. An L7-healthy / L4-unhealthy endpoint is "app is fine, node is slow." An L4-healthy / L7-unhealthy endpoint is "TCP is up, app is broken."

## L7 connection drain

When a pod is being deleted (rolling update), the L7 layer must:

1. Stop sending *new* requests to the pod.
2. Let *existing* connections finish (or be force-closed after a timeout).

The `nginx.ingress.kubernetes.io/connection-drain-timeout` annotation (if your chart supports it) or the `preStop` hook on the pod controls this. See `03` for the lab.
