# TLS and mTLS — A Full Hands-On Lesson (openssl → Go)

> From zero: what a certificate *is*, how a CA signs a **leaf/child** cert, how the
> chain verifies, and **how to generate and verify all of it yourself** — first with
> `openssl`, then as a complete Go program. This is the lab companion to
> [`certificates-and-pki.md`](certificates-and-pki.md) (concepts) and
> [`verification-and-testing.md`](verification-and-testing.md) (ops tooling).

**How to use this doc:** type every command. Don't paste the Go code — write it. The
muscle memory is the point. By the end you'll have a working mini-PKI, an mTLS server
and client in Go, and the ability to read any certificate chain on sight.

## Part 0 — The 60-second refresher

Skip if you just read [`how-it-works.md`](how-it-works.md).

```
  A certificate binds a NAME to a PUBLIC KEY.
  A CA is just a keypair whose public half everyone agreed to trust.
  Signing = the CA's private key makes a signature over the leaf's contents.

  ┌────────────┐    signs     ┌────────────┐    signs    ┌──────────────┐
  │  ROOT CA   │ ───────────► │ INTERMEDIATE│ ──────────► │  LEAF (child)│
  │ (trusted,  │              │ CA (also a │             │ your server  │
  │  offline)  │              │ cert)      │             │ or client    │
  └────────────┘              └────────────┘             └──────────────┘

  Verification walks the chain upward: leaf → intermediate → root,
  checking each signature, until it hits a cert already in the trust store.
```

**Three words you must never mix up again:**

| Term | Meaning |
|------|---------|
| **Root CA** | self-signed; sits in the trust store; private key ideally offline |
| **Intermediate CA** | signed by the root; does the day-to-day signing; must have `CA:TRUE` |
| **Leaf / child / end-entity** | signed by an intermediate; `CA:FALSE`; the cert a server or client actually presents |

## Part 1 — Build a mini-PKI with openssl

We will make, in order: **root CA → intermediate CA → server leaf → client leaf**. The
client leaf is what makes **mTLS** possible later.

### 1.0 Workspace

```bash
mkdir -p pki-lab && cd pki-lab
```

Everything below runs in this directory.

### 1.1 The root CA

```bash
# 1. The root PRIVATE KEY (ECDSA P-256 — modern default; RSA 4096 also fine)
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 \
    -out root-ca.key
chmod 600 root-ca.key

# 2. The root CERTIFICATE (self-signed — the root signs itself)
openssl req -x509 -new -key root-ca.key -sha256 -days 3650 \
    -subj "/C=US/O=ExpenseTracker Lab/CN=Lab Root CA" \
    -addext "basicConstraints=critical,CA:TRUE,pathlen:1" \
    -addext "keyUsage=critical,keyCertSign,cRLSign" \
    -out root-ca.crt
```

**What each flag did:**

| Flag | Why |
|------|-----|
| `-x509` | output a certificate directly (not a CSR) |
| `-days 3650` | roots live long; they're a pain to rotate |
| `basicConstraints=critical,CA:TRUE` | **this cert may sign others** — without `CA:TRUE` a "CA" can't sign anything browsers/Go will accept |
| `pathlen:1` | this root may sign intermediates, which may sign leaves — but nothing deeper. Limits blast radius |
| `keyUsage=keyCertSign,cRLSign` | this key's only job: sign certs and revocation lists |

**Verify it:**

```bash
openssl x509 -in root-ca.crt -noout -text | grep -E "CA:|Key Usage" -A1
```

You should see `CA:TRUE, pathlen:1` and `Certificate Sign`.

### 1.2 The intermediate CA (a "child CA")

The intermediate is a normal cert **signed by the root**, with `CA:TRUE` so it can
itself sign leaves.

```bash
# 1. Intermediate private key
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 \
    -out intermediate-ca.key
chmod 600 intermediate-ca.key

# 2. CSR (Certificate Signing Request) — the "please sign me" document
openssl req -new -key intermediate-ca.key \
    -subj "/C=US/O=ExpenseTracker Lab/CN=Lab Intermediate CA 1" \
    -out intermediate-ca.csr

# 3. The ROOT signs the intermediate's CSR
openssl x509 -req -in intermediate-ca.csr \
    -CA root-ca.crt -CAkey root-ca.key -CAcreateserial \
    -days 1825 -sha256 \
    -extfile <(printf "%s\n" \
      "basicConstraints=critical,CA:TRUE,pathlen:0" \
      "keyUsage=critical,keyCertSign,cRLSign") \
    -out intermediate-ca.crt
```

**Two things that are new vs the root:**

1. **The CSR flow.** Keys are generated by the *child*; the parent never sees the
   child's private key. The CSR contains the public key + identity, and the parent
   signs *that*. This is the whole PKI pattern — delegation without key sharing.
2. **`pathlen:0`** — the intermediate may sign *leaves* but not further CAs. The chain
   is exactly root → intermediate → leaf, no deeper.

**Build the chain file (leaf-presenters need it):**

```bash
cat intermediate-ca.crt root-ca.crt > chain.pem
```

### 1.3 The server leaf

```bash
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 -out server.key
chmod 600 server.key

openssl req -new -key server.key \
    -subj "/CN=api.expense.local" \
    -addext "subjectAltName=DNS:api.expense.local,DNS:expense.local,IP:127.0.0.1" \
    -out server.csr

openssl x509 -req -in server.csr \
    -CA intermediate-ca.crt -CAkey intermediate-ca.key -CAcreateserial \
    -days 825 -sha256 \
    -extfile <(printf "%s\n" \
      "basicConstraints=critical,CA:FALSE" \
      "keyUsage=critical,digitalSignature,keyEncipherment" \
      "extendedKeyUsage=serverAuth" \
      "subjectAltName=DNS:api.expense.local,DNS:expense.local,IP:127.0.0.1") \
    -out server.crt

# the server's full chain = leaf + intermediate (root stays in the client's store)
cat server.crt intermediate-ca.crt > server-fullchain.pem
```

**The leaf extensions decoded:**

| Extension | Value here | Meaning |
|-----------|-----------|---------|
| `basicConstraints` | `CA:FALSE` | **may not sign anything.** A leaf that could sign would be a catastrophic mis-issuance |
| `keyUsage` | `digitalSignature` (+ `keyEncipherment` for RSA) | proves key possession in the handshake (TLS 1.3's CertificateVerify) |
| `extendedKeyUsage` | `serverAuth` | this leaf is for **servers**. A `clientAuth` leaf cannot serve TLS |
| `subjectAltName` | DNS + IP entries | **the only field clients match against.** CN alone is ignored by Go and modern browsers |

**Verify the whole chain from the leaf:**

```bash
# -untrusted supplies intermediates; the root must be findable via -CAfile
openssl verify -CAfile root-ca.crt -untrusted intermediate-ca.crt server.crt
# → server.crt: OK
```

If that prints `OK`, your PKI is internally consistent. The two classic failures:

```
error 20 at 0 depth: unable to get local issuer certificate
  → you forgot the intermediate somewhere (signing or verifying)

error 24: invalid CA certificate
  → basicConstraints wasn't CA:TRUE on the intermediate, or pathlen was violated
```

### 1.4 The client leaf (the "m" in mTLS)

```bash
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 -out client.key
chmod 600 client.key

openssl req -new -key client.key \
    -subj "/CN=expense-tracker-client" \
    -out client.csr

openssl x509 -req -in client.csr \
    -CA intermediate-ca.crt -CAkey intermediate-ca.key -CAcreateserial \
    -days 825 -sha256 \
    -extfile <(printf "%s\n" \
      "basicConstraints=critical,CA:FALSE" \
      "keyUsage=critical,digitalSignature" \
      "extendedKeyUsage=clientAuth") \
    -out client.crt

cat client.crt intermediate-ca.crt > client-fullchain.pem
```

**The only difference from the server leaf: `extendedKeyUsage=clientAuth`.** A cert
with `serverAuth` cannot be used as a client cert (and vice versa) if the peer
enforces EKU — Go does.

```
  THE COMPLETE LAB PKI:

  root-ca.key / root-ca.crt                     (keep the key OFFLINE-ish)
    └── intermediate-ca.key / intermediate-ca.crt
          ├── server.key  / server.crt          (serverAuth)
          └── client.key  / client.crt          (clientAuth)

  chain.pem            = intermediate + root    (verification bundle)
  server-fullchain.pem = server + intermediate  (what the SERVER presents)
  client-fullchain.pem = client + intermediate  (what the CLIENT presents)
```

## Part 2 — Prove it works: openssl TLS + mTLS

### 2.1 Plain TLS (server-only auth)

```bash
# terminal 1 — a TLS server using the leaf
openssl s_server \
    -key server.key -cert server-fullchain.pem \
    -accept 8443 -www

# terminal 2 — a client that trusts the lab root
openssl s_client -connect 127.0.0.1:8443 \
    -CAfile root-ca.crt \
    -verify_hostname api.expense.local
```

Look for `Verify return code: 0 (ok)` in the client output. Now break it on purpose —
the fastest PKI education there is:

```bash
# a) verify WITHOUT supplying the root → unknown-issuer failure
openssl s_client -connect 127.0.0.1:8443 -verify_hostname api.expense.local </dev/null
#   → verify error: self-signed certificate in certificate chain (or similar)

# b) request the WRONG hostname → SAN mismatch
openssl s_client -connect 127.0.0.1:8443 -CAfile root-ca.crt \
    -verify_hostname wrong.example.com </dev/null
#   → Verification error: Hostname mismatch
```

### 2.2 mTLS (mutual auth)

mTLS = the server *also* demands and verifies a client certificate.

```bash
# terminal 1 — same server, now REQUIRING a client cert signed by our CA
openssl s_server \
    -key server.key -cert server-fullchain.pem \
    -CAfile root-ca.crt \
    -Verify 1 \
    -accept 8443 -www
#          ^^^^^^^ capital -Verify = REQUIRE (fail if absent), depth 1

# terminal 2 — client presents ITS cert
openssl s_client -connect 127.0.0.1:8443 \
    -CAfile root-ca.crt -verify_hostname api.expense.local \
    -cert client-fullchain.pem -key client.key
```

**The trust model of mTLS, in one picture:**

```
   PLAIN TLS                                mTLS
   ─────────                                ────
   client verifies SERVER's cert            client verifies SERVER's cert
                                            server verifies CLIENT's cert
                                            (against the same root, or a
                                             dedicated client CA)

   identity proven: server                  identity proven: BOTH

   use case: public web                     use case: service-to-service,
                                            internal APIs, zero-trust meshes
```

**Now the two failure drills that teach the most:**

```bash
# a) no client cert at all → handshake fails
openssl s_client -connect 127.0.0.1:8443 -CAfile root-ca.crt </dev/null
#   → alert certificate required

# b) a client cert the server's CA didn't sign → handshake fails
#    (generate a ROGUE CA + client, then present the rogue client)
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 -out rogue-ca.key
openssl req -x509 -new -key rogue-ca.key -days 30 \
    -subj "/CN=Rogue CA" -addext "basicConstraints=critical,CA:TRUE" \
    -out rogue-ca.crt
# ... sign a client cert with it as in 1.4, then:
openssl s_client -connect 127.0.0.1:8443 -CAfile root-ca.crt \
    -cert rogue-client.crt -key rogue-client.key </dev/null
#   → handshake fails; server rejects untrusted client chain
```

When you can predict both failures before running them, you understand mTLS.

## Part 3 — The same thing in Go, from basics up

Go's standard library makes TLS a first-class citizen — `crypto/tls` + `crypto/x509`
are all you need. We build up in five levels.

### 3.0 Level 0 — read a certificate like `openssl x509 -text`

```go
// inspect.go
package main

import (
	"crypto/x509"
	"encoding/pem"
	"fmt"
	"os"
)

func main() {
	raw, err := os.ReadFile(os.Args[1])
	must(err)

	block, _ := pem.Decode(raw) // PEM = base64 + headers; the DER is inside
	if block == nil || block.Type != "CERTIFICATE" {
		panic("not a PEM certificate")
	}

	cert, err := x509.ParseCertificate(block.Bytes) // DER → struct
	must(err)

	fmt.Println("Subject:      ", cert.Subject.CommonName)
	fmt.Println("Issuer:       ", cert.Issuer.CommonName)
	fmt.Println("Is CA:        ", cert.IsCA)
	fmt.Println("DNS names:    ", cert.DNSNames)
	fmt.Println("IP addresses: ", cert.IPAddresses)
	fmt.Println("Key usage:    ", cert.KeyUsage)
	fmt.Println("Ext key usage:", cert.ExtKeyUsage) // 1 = serverAuth, 2 = clientAuth
	fmt.Println("Not before:   ", cert.NotBefore)
	fmt.Println("Not after:    ", cert.NotAfter)
}

func must(err error) {
	if err != nil {
		panic(err)
	}
}
```

```bash
go run inspect.go server.crt
# Is CA: false, DNS names: [api.expense.local ...], Ext key usage: [1]
```

**The mental model:** `pem.Decode` strips the ASCII armor; `x509.ParseCertificate`
gives you every field as plain Go data. Everything openssl showed you is a struct
field now.

### 3.1 Level 1 — verify a chain manually (the Go version of `openssl verify`)

```go
// verify.go
package main

import (
	"crypto/x509"
	"encoding/pem"
	"fmt"
	"os"
)

func loadCert(path string) (*x509.Certificate, error) {
	raw, err := os.ReadFile(path)
	if err != nil {
		return nil, err
	}
	block, _ := pem.Decode(raw)
	if block == nil {
		return nil, fmt.Errorf("no PEM block in %s", path)
	}
	return x509.ParseCertificate(block.Bytes)
}

func main() {
	root, err := loadCert("root-ca.crt")
	must(err)
	inter, err := loadCert("intermediate-ca.crt")
	must(err)
	leaf, err := loadCert("server.crt")
	must(err)

	roots := x509.NewCertPool()
	roots.AddCert(root)

	intermediates := x509.NewCertPool()
	intermediates.AddCert(inter)

	opts := x509.VerifyOptions{
		Roots:         roots,
		Intermediates: intermediates,
		DNSName:       "api.expense.local", // triggers SAN matching
	}

	chains, err := leaf.Verify(opts)
	if err != nil {
		fmt.Println("VERIFY FAILED:", err)
		os.Exit(1)
	}
	fmt.Printf("OK — %d chain(s) found\n", len(chains))
	for i, c := range chains[0] {
		fmt.Printf("  [%d] %s\n", i, c.Subject.CommonName)
	}
	// → [0] api.expense.local
	//   [1] Lab Intermediate CA 1
	//   [2] Lab Root CA
}

func must(err error) {
	if err != nil {
		panic(err)
	}
}
```

**The three things `Verify` checks** (and errors it returns when they fail):

| Check | Error on failure |
|-------|------------------|
| signatures link leaf → intermediate → root | `x509: certificate signed by unknown authority` |
| SANs contain `opts.DNSName` | `x509: certificate is valid for X, not Y` |
| validity window (`NotBefore..NotAfter`) | `x509: certificate has expired or is not yet valid` |

Also note EKU is checked *at handshake time* by `crypto/tls`, not by `Verify` —
`Verify` is chain logic only.

### 3.2 Level 2 — a TLS server in Go (using our leaf)

```go
// server.go
package main

import (
	"crypto/tls"
	"fmt"
	"net/http"
)

func main() {
	// LoadCertificate/leaf+key pairs the files and checks the key matches the cert
	cert, err := tls.LoadX509KeyPair("server-fullchain.pem", "server.key")
	must(err)

	tlsCfg := &tls.Config{
		Certificates: []tls.Certificate{cert},
		MinVersion:   tls.VersionTLS13,
	}

	srv := &http.Server{
		Addr:      ":8443",
		Handler:   http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			fmt.Fprintf(w, "hello over TLS, from %s\n", r.TLS.ServerName)
		}),
		TLSConfig: tlsCfg,
	}
	fmt.Println("listening on :8443")
	must(srv.ListenAndServeTLS("", "")) // cert/key come from TLSConfig
}
```

```bash
go run server.go
# in another terminal — your Part-1 client still works against it:
openssl s_client -connect 127.0.0.1:8443 -CAfile root-ca.crt \
    -verify_hostname api.expense.local
```

**Why `LoadX509KeyPair` and not two separate loads:** it also verifies the private key
actually corresponds to the certificate's public key — a mismatch is caught at
startup, not at first handshake.

### 3.3 Level 3 — a TLS **client** in Go that verifies properly

The single most common Go TLS bug in the wild is skipping verification. This is the
correct version:

```go
// client.go
package main

import (
	"crypto/tls"
	"crypto/x509"
	"fmt"
	"net/http"
	"os"
)

func main() {
	rootPEM, err := os.ReadFile("root-ca.crt") // trust ONLY our lab root
	must(err)

	roots := x509.NewCertPool()
	if !roots.AppendCertsFromPEM(rootPEM) {
		panic("failed to add root cert to pool")
	}

	client := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{
				RootCAs:    roots,                          // chain verification
				ServerName: "api.expense.local",           // SAN verification
				MinVersion: tls.VersionTLS13,
			},
		},
	}

	resp, err := client.Get("https://127.0.0.1:8443/")
	must(err)
	defer resp.Body.Close()
	fmt.Println("status:", resp.Status)
}
```

**Three deliberate choices worth internalizing:**

1. **`RootCAs` is our pool, not the system's.** Default Go uses the OS store (Verisign,
   DigiCert, ...). Our lab root isn't there, so we supply it. In prod against public
   CAs you'd omit `RootCAs` entirely.
2. **`ServerName` is set explicitly** because we dialed an IP (`127.0.0.1`). Go can't
   infer the name from an IP URL, so verification would fail without this. When you
   dial `https://api.expense.local:8443/`, Go sets it for you.
3. **Never `InsecureSkipVerify: true`.** That disables *everything this lesson built*.
   The only legitimate use is a deliberate test you delete before merging.

### 3.4 Level 4 — **mTLS** in Go (both directions)

Server requires + verifies client certs:

```go
// mtls-server.go
package main

import (
	"crypto/tls"
	"crypto/x509"
	"fmt"
	"net/http"
	"os"
)

func main() {
	serverCert, err := tls.LoadX509KeyPair("server-fullchain.pem", "server.key")
	must(err)

	clientRoots := x509.NewCertPool() // the CA(s) allowed to sign CLIENTS
	pem, err := os.ReadFile("root-ca.crt")
	must(err)
	clientRoots.AppendCertsFromPEM(pem)

	tlsCfg := &tls.Config{
		Certificates: []tls.Certificate{serverCert},
		ClientAuth:   tls.RequireAndVerifyClientCert, // ★ mTLS starts here
		ClientCAs:    clientRoots,                    // ...and here
		MinVersion:   tls.VersionTLS13,
	}

	srv := &http.Server{
		Addr:      ":8443",
		TLSConfig: tlsCfg,
		Handler: http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			if len(r.TLS.PeerCertificates) == 0 { // can't happen with Require..., but
				http.Error(w, "no client cert", http.StatusUnauthorized)
				return
			}
			cn := r.TLS.PeerCertificates[0].Subject.CommonName
			fmt.Fprintf(w, "mTLS OK — authenticated as %q\n", cn)
		}),
	}
	fmt.Println("mTLS server on :8443")
	must(srv.ListenAndServeTLS("", ""))
}
```

The client presents its cert:

```go
// mtls-client.go
package main

import (
	"crypto/tls"
	"crypto/x509"
	"fmt"
	"io"
	"net/http"
	"os"
)

func main() {
	clientCert, err := tls.LoadX509KeyPair("client-fullchain.pem", "client.key")
	must(err)

	roots := x509.NewCertPool()
	pem, _ := os.ReadFile("root-ca.crt")
	roots.AppendCertsFromPEM(pem)

	client := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{
				Certificates: []tls.Certificate{clientCert}, // ★ present OUR cert
				RootCAs:      roots,
				ServerName:   "api.expense.local",
				MinVersion:   tls.VersionTLS13,
			},
		},
	}

	resp, err := client.Get("https://127.0.0.1:8443/")
	must(err)
	defer resp.Body.Close()
	body, _ := io.ReadAll(resp.Body)
	fmt.Print(string(body)) // → mTLS OK — authenticated as "expense-tracker-client"
}
```

**`ClientAuth` modes, ranked:**

| Mode | Behavior |
|------|----------|
| `NoClientCert` | plain TLS |
| `RequestClientCert` | ask; proceed either way (rarely what you want) |
| `VerifyClientCertIfGiven` | verify if presented, allow anonymous |
| `RequireAnyClientCert` | require one — but **don't verify against ClientCAs** ⚠ |
| **`RequireAndVerifyClientCert`** | **require + verify chain + EKU. The mTLS default you want** |

**The full mTLS handshake in one picture** — notice both cert presentations:

```
  Client                                       Server
    │ ── ClientHello ──────────────────────────► │
    │                                           │ (requests client cert
    │ ◄─ ServerHello + CertificateReq ────────── │  via CertificateRequest)
    │ ◄─ {Certificate, CertVerify, Finished} ── │ ← server's leaf presented
    │                                           │   client verifies chain+SAN+EKU(serverAuth)
    │ ── {Certificate, CertVerify, Finished} ─► │ ← client's leaf presented
    │                                           │   server verifies chain+EKU(clientAuth)
    │ ══════ encrypted app data, both known ════ │
```

### 3.5 Level 5 — generating certs *in Go* (a private CA as code)

Everything openssl did in Part 1, as a program — this is exactly how tools like
smallstep/cert-manager work internally:

```go
// mini-ca.go — go run mini-ca.go
package main

import (
	"crypto/ecdsa"
	"crypto/elliptic"
	"crypto/rand"
	"crypto/x509"
	"crypto/x509/pkix"
	"encoding/pem"
	"fmt"
	"math/big"
	"os"
	"time"
)

func main() {
	// ---- 1. root ------------------------------------------------------
	rootKey, _ := ecdsa.GenerateKey(elliptic.P256(), rand.Reader)
	rootTmpl := &x509.Certificate{
		SerialNumber: big.NewInt(1),
		Subject:      pkix.Name{CommonName: "Go Lab Root", Organization: []string{"Lab"}},
		NotBefore:    time.Now().Add(-time.Hour), // small backdate: clock-skew safety
		NotAfter:     time.Now().AddDate(10, 0, 0),
		IsCA:         true,
		KeyUsage:     x509.KeyUsageCertSign | x509.KeyUsageCRLSign,
		BasicConstraintsValid: true,
		MaxPathLen: 1,
	}
	// self-signed: the root signs its own template with its own key
	rootDER, _ := x509.CreateCertificate(rand.Reader, rootTmpl, rootTmpl, &rootKey.PublicKey, rootKey)
	rootCert, _ := x509.ParseCertificate(rootDER)

	// ---- 2. leaf -------------------------------------------------------
	leafKey, _ := ecdsa.GenerateKey(elliptic.P256(), rand.Reader)
	leafTmpl := &x509.Certificate{
		SerialNumber: big.NewInt(2),
		Subject:      pkix.Name{CommonName: "api.go-lab.local"},
		DNSNames:     []string{"api.go-lab.local"}, // ★ SAN, never just CN
		NotBefore:    time.Now().Add(-time.Hour),
		NotAfter:     time.Now().AddDate(0, 0, 90),
		KeyUsage:     x509.KeyUsageDigitalSignature,
		ExtKeyUsage:  []x509.ExtKeyUsage{x509.ExtKeyUsageServerAuth},
	}
	// signed by the ROOT: parent = rootCert, parent key = rootKey
	leafDER, _ := x509.CreateCertificate(rand.Reader, leafTmpl, rootCert, &leafKey.PublicKey, rootKey)

	writePEM("go-root-ca.crt", "CERTIFICATE", rootDER)
	writePEM("go-server.crt", "CERTIFICATE", leafDER)
	writeKey("go-server.key", leafKey)
	fmt.Println("wrote go-root-ca.crt, go-server.crt, go-server.key")
}

func writePEM(path, typ string, der []byte) {
	f, _ := os.Create(path)
	pem.Encode(f, &pem.Block{Type: typ, Bytes: der})
	f.Close()
}
func writeKey(path string, key *ecdsa.PrivateKey) {
	der, _ := x509.MarshalECPrivateKey(key)
	f, _ := os.Create(path)
	pem.Encode(f, &pem.Block{Type: "EC PRIVATE KEY", Bytes: der})
	f.Close()
}
```

**Read the two `CreateCertificate` calls carefully — the whole PKI idea is in their
arguments:**

```
x509.CreateCertificate(rand, TEMPLATE, PARENT, SUBJECT_PUBLIC_KEY, PARENT_PRIVATE_KEY)
                              │           │        │                    │
root:  tmpl == parent, key signs itself ──┘        │                    └── rootKey
leaf:  tmpl=leaf,  parent=rootCert ────────────────┘                        └── rootKey
                   (the CA's identity            leaf's PUBLIC key
                    gets embedded in AuthorityKeyId) (never the private key!)
```

Verify with the tools you already trust:

```bash
go run mini-ca.go
openssl verify -CAfile go-root-ca.crt go-server.crt   # → go-server.crt: OK
```

## Part 4 — The checklist you now own

Type these from memory; that's the real deliverable of this lesson:

```
BUILD A CA + LEAF (openssl)
  1. root:     genpkey → req -x509 with CA:TRUE,pathlen:1, keyCertSign
  2. intermedi:genpkey → req (CSR) → x509 -req signed by root, CA:TRUE,pathlen:0
  3. leaf:     genpkey → req (CSR + SAN!) → x509 -req signed by intermediate,
               CA:FALSE, serverAuth|clientAuth, SANs
  4. fullchain = leaf + intermediate; verify with: openssl verify -CAfile root
     -untrusted intermediate leaf

BREAK IT (and name the error)
  · omit intermediate          → error 20 / "unknown authority"
  · wrong hostname             → SAN mismatch
  · expired                    → error 10
  · client cert not from CA    → handshake alert on mTLS
  · serverAuth cert as client  → EKU rejection (Go: "certificate specifies an
                                  incompatible key usage")

GO
  · parse:      pem.Decode → x509.ParseCertificate
  · verify:     leaf.Verify{Roots, Intermediates, DNSName}
  · server:     tls.LoadX509KeyPair → Config{Certificates, MinVersion: TLS13}
  · client:     Config{RootCAs, ServerName} — and never InsecureSkipVerify
  · mTLS:       server Config{ClientAuth: RequireAndVerifyClientCert, ClientCAs};
                client Config{Certificates: [clientCert]}
  · CA-as-code: x509.CreateCertificate(rand, tmpl, parent, subjectPub, parentKey)
```

## Part 5 — Where this plugs into the expense tracker

- **The edge cert** (server leaf) is exactly Part 1.3 — only the issuer differs
  (Let's Encrypt via DNS-01, or self-signed lab CA — see
  [`this-project-topology.md`](this-project-topology.md)).
- **mTLS is the "for scale" answer** to "should services inside the cluster
  authenticate each other?" — the Part 3.4 pattern, issued per-workload by a private
  CA (cert-manager's `ca` issuer is literally Part 3.5). Not needed on a single node,
  but it's the mental model for service meshes.
- **A Go health-checker or CLI client** for this API would be Part 3.3 verbatim: trust
  the project root, set `ServerName`, never skip verify.
- The **rogue-CA drill** (2.2b) is the cheapest way to prove to yourself a deployment
  actually verifies client chains rather than accepting anything.
